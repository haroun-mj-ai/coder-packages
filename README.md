# coder-packages

Haroun's personal layer on top of [`coder-nix-devenv`](https://github.com/haroun-mj-ai/coder-nix-devenv).

The base repo is the toolchain **everyone** on the team installs. This one holds
the things only I want — extra packages, git hooks, and Claude Code skills — so
they never land in the shared template. It composes on top of the base flake as
an input; nothing is copied or forked.

> Why a separate repo and not a fork? GitHub will not let a single account own
> both a parent and its fork, and `coder-nix-devenv` is already mine.

## Quick start

```bash
# extras only, on top of a workspace that already has the base toolchain
nix profile add github:haroun-mj-ai/coder-packages

# or base toolchain + extras, on a workspace starting from nothing
nix profile add github:haroun-mj-ai/coder-packages#full
```

A throwaway shell instead of installing:

```bash
nix develop github:haroun-mj-ai/coder-packages          # extras
nix develop github:haroun-mj-ai/coder-packages#full     # base + extras
nix run  github:haroun-mj-ai/coder-packages#roborev -- version
```

`roborev` has no nixpkgs attribute, so `pkgs/roborev.nix` packages it from the
upstream release tarballs (all four platform hashes taken from upstream's
published `SHA256SUMS`). The binaries are static-pie, so there is no linker to
patch and no reason to rebuild from source.

## Git hooks

`hooks/commit-msg` appends my two mandatory `Co-Authored-By` trailers and strips
any assistant/model co-author trailer. It is built on
`git interpret-trailers --if-exists addIfDifferent`, so it is idempotent, keeps a
genuine third-party co-author, and places trailers correctly even under
`git commit -v`.

```bash
./scripts/install-hooks.sh                 # wire the JourneyAI checkout + siblings
./scripts/install-hooks.sh --check         # verify, non-zero exit if any are missing
./scripts/install-hooks.sh /path/to/repo   # wire an arbitrary repo
```

It sets each repo's `core.hooksPath` to this repo's `hooks/`. That lives in
`.git/config`, which git does not track, so it runs once per clone per machine.

Two limits worth knowing:

- **It only covers local commits** — `git commit`, `--amend`, merges. Commits
  made through the GitHub API (the MCP write tools, a web-UI squash-merge) run
  no local hook, so the trailers have to be written by hand there.
- **`core.hooksPath` is exclusive.** Anything that installs into `.git/hooks`
  is ignored once it is set. roborev is well-behaved and installs its
  `post-commit` / `post-rewrite` into the configured hooks dir instead, so the
  two coexist.

## Claude Code config

`claude/` holds my Claude Code setup, kept here so it travels between machines:

| Path | What |
| --- | --- |
| `claude/skills/` | `implement-issue`, `ship-work`, `orchestration-run-analysis` (plus retired `plan-issue`/`implement-plan` stubs) |
| `claude/agents/` | `explorer`, `implementer`, `plan-critic`, `scout`, `spec-auditor` |
| `claude/AGENTS.md` | agent workflow rules — Linear, commits, quality gates, shipping |

**This repo is the only tracked home for the skills and agents.** They are
gitignored in the JourneyAI org repo (`.claude/skills/`, `.claude/agents/`), so
personal workflow changes never land there. Edit them here, commit here, push
here.

`claude/AGENTS.md` is the exception. It is team workflow and stays tracked in the
org repo; the copy here is a portable mirror, and the org repo wins if they
diverge.

To use them in a checkout, symlink or copy them into that repo's `.claude/`:

```bash
ln -s ~/coder-packages/claude/skills ~/root-for-local/.claude/skills
ln -s ~/coder-packages/claude/agents ~/root-for-local/.claude/agents
```

## Adding a package

Add it to `extraAttrs` in `flake.nix` and nowhere else, then regenerate the
table:

```bash
./scripts/export-packages.sh   # paste the output over the table above
```

If it is not in nixpkgs, add a derivation under `pkgs/` and `callPackage` it in,
the way `roborev` is done.
